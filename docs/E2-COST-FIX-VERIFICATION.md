## 1. السياسة المنفذة حرفيًا

| المطلوب في الاعتماد | المنفَّذ |
|---|---|
| الإنشاء يجمّد التكلفة كتقدير فقط | `addLine` يخزن avg الحالي كتقدير بصري — لا يُستخدم للترحيل |
| عند الاعتماد: إعادة قراءة متوسط الصنف في مخزن المصدر **داخل المعاملة نفسها** | `lockWarehouseAverageCost()` — يُستدعى داخل `db.transaction` بعد تحميل السند بـ `FOR UPDATE` |
| نفس التكلفة تستخدم في: أسطر السند، إجمالي القيمة، قيد إخراج المخزون (1108/1104)، حركة `transferOut`، سند الإخراج، تقرير «البضاعة في الطريق» | الكل يقرأ من `costByItem` (خريطة item→متوسط مقفولة لحظيًا)؛ السطر يُعاد تحديثه في الداتابيز إن لزم؛ `total_value` تُعاد حسابته؛ الحركة والقيود وvoucher lines تستخدم نفس الرقم |
| التزامن: قفل على صفوف `item_warehouse_qty` | `SELECT … FOR UPDATE` على صف لكل صنف — يُقفل مرة واحدة لكل صنف (مرتبًا بـ `itemId` تصاعديًا لمنع deadlock) ويُستخدم لجميع أسطره |
| الكمية تُعاد قراءتها/التحقق عند الاعتماد (ليست لوقت إضافة السطر فقط) | `available` يُقرأ في نفس القفل ويُرفض بدونه: «الكمية في المخزن غير كافية للصنف «…» (المتاح 1، المطلوب 5)» → HTTP 400 |
| التكلفة عند الاستلام = التكلفة المعتمدة المحفوظة (لا إعادة تقييم) | `receive()` يقرأ `line.unit_cost` فقط بعد الاعتماد — لم يتغير |
| الإلغاء قبل الاستلام يعكس قيد الاعتماد بنفس التكلفة المحفوظة حرفيًا | `cancel()` يقرأ `line.unit_cost` — لم يتغير |
| أكثر من سطر للصنف نفسه | يُجمع `qty` لكل صنف ويُقفل مرة واحدة ويُستخدم نفس السعر لكل أسطر الصنف (مُثبت عمليًا بقواعد PCS/PKT — سطران بنفس cost=700) |
| تطبيق نفس السياسة على التحويل داخل الفرع | `StockTransferService` مُعدَّل بنفس السياسة (CF7 = 600 لا 800) |
