# تحليل فجوات الإعدادات المتقدمة (settings-advanced) وربطه بخطة العمل

> **المصدر:** `docs/ezees-guide/settings-advanced.txt` و `docs/ezees-guide/settings-advanced.html` (دليل Ezees ERP — "الإعدادات المتقدمة: الطباعة ونقاط البيع والسيرفر والاتصال"، آخر تحديث بالمصدر: 2026-10-10).
>
> **مقارنة مع:** حالة WaselERP الحالية (Next.js 14 static/PWA + NestJS 10 + PostgreSQL + Print Agent محلي + ETA/ZATCA) وملفات الخطة: `docs/EEYES-STEPS.md`, `docs/EZEES-COVERAGE.md`, `docs/ARCHITECTURE.md`, `AGENTS.md`.
>
> **تاريخ التحليل:** 2026-11-14 (تحليل ثابت/مقارنة قدرات). لا يفترض تنفيذًا غير موجود في الكود.

## 1) ملخص تنفيذي

| المؤشر | النتيجة |
|---|---|
| محاور الدليل | 11 تبويبًا/قسمًا رئيسيًا + شاشة اتصال قاعدة البيانات + إعداد السيرفر للاتصال عن بعد + رسائل شائعة |
| منطبق مباشرة على معمارية WaselERP | **جزئي (≈25–35%)** — أغلبه يدخل ضمن إعدادات النظام، الطباعة عبر Print Agent، POS، HR، المرفقات/الإشعارات، والنسخ الاحتياطي |
| غير منطبق (اختلاف معماري Desktop/SQL Server) | **≈35–45%** — إعداد اتصال DB من العميل، إعداد SQL Server/sa/منافذ، مزامنة OnLine/OffLine بقواعد محلية، إعدادات جهاز محلي بالمعنى التقليدي لتطبيق سطح مكتب |
| موجود جزئيًا/بصيغة مختلفة | **≈20–30%** — إعدادات عامة/ضرائب، طباعة حرارية عبر وكيل، فروع/صلاحيات، موارد بشرية أساسية، ETA/ZATCA |

**الخلاصة:** مرجع `settings-advanced` غني لكنه موجه لمنتج **سطح مكتب (Ezees/SQL Server)**. في WaselERP يجب تحويل المتطلبات "القابلة للتطبيق" إلى إعدادات مركزية (DB + صلاحيات) وخيارات عميل/وكيل طباعة، مع **استبعاد/إعادة تعريف** ما يتعلق باتصال SQL Server، أوفلاين بقواعد فرعية، وأجهزة COM/بصمة بالطريقة الموصوفة إلا عند وجود تكامل مكافئ.

## 2) مصفوفة الفجوات التفصيلية حسب أقسام الدليل

### 2.1 تبويب «إعدادات الطابعة» (طباعة الفواتير + طباعة POS)

| بند الدليل | الحالة في WaselERP | الفجوة | الانطباق | الربط بالخطة |
|---|---|---|---|---|
| اختيار طابعة الفواتير/التقارير لكل جهاز | ❌ غير موجود كإعداد في الويب؛ الطباعة عبر Print Agent محلي (`apps/print-agent`) أو طباعة المتصفح | لا توجد شاشة إعداد طابعات/تعيين طابعة افتراضية لكل محطة/مستخدم من داخل النظام | منطبق جزئيًا (عبر إعدادات الوكيل/الجهاز) | **P7 — الإعدادات والأدوات** (إعدادات فرع/جهاز، طباعة وتقارير) + تحسين Print Agent |
| نوع الطباعة (A4/A5 عادي، حراري/إيصال) | 🟡 جزئي — Print Agent يدعم ESC/POS حراري؛ طباعة متصفح متاحة | لا توجد سياسة موحدة لأنواع القوالب (A4/A5/حراري 80/57) قابلة للضبط لكل سياق مستند | منطبق | **P7** + "دعم طابعة A4 رسمية" (متبقٍ مذكور في AGENTS) |
| مقاس الفاتورة/البون (A4/A5/80mm/57mm) | 🟡 جزئي (حراري مدعوم عمليًا) | لا إعداد مقاس/قالب لكل نوع مستند من الواجهة | منطبق | **P7** / Print Agent |
| هوامش الورق | ❌ | غير مدعوم كإعداد مركزي | منطبق (لتقارير/A4) | **P7** |
| طابعة إيصال العميل / طابعة ورقة المطبخ | 🟡 جزئي — Print Agent للطباعة؛ أوامر مطبخ/مطعم موجودة (Gate 3) | لا فصل صريح لتوجيه الطباعة (كاشير vs مطبخ) بإعدادات لكل محطة/قسم | منطبق جزئيًا | **P7** + تحسينات المطاعم/المطبخ (ما بعد Gate 3) |
| طباعة إيصال كاشير حراري مباشر vs معاينة A4 | 🟡 جزئي | سلوك يعتمد على التنفيذ الحالي/الوكيل؛ لا مفتاح إعداد واضح في UI | منطبق | **P7** |
| عدد النسخ (إيصال/مطبخ/أذون) | ❌ | لا إعداد عدد نسخ لكل نوع مستند | منطبق | **P7** / Print Agent |

**حالة WaselERP الحالية ذات الصلة:** Print Agent محلي (ESC/POS، درج نقدية، طابعات شبكة) — راجع `apps/print-agent/README.md`, `apps/web/lib/print.ts`, AGENTS (§5). لا توجد تبويبات "إعدادات طابعة لكل جهاز" في `apps/web/app/admin/page.tsx`.

## 3) فجوات عرضية (Cross-cutting) مستنتجة من الدليل

1. **إعدادات على مستوى "الجهاز/المحطة" مقابل "الفرع/النظام"**: الدليل يفرق بوضوح (طابعة/باركود/مظهر محلي، مقابل إعدادات عامة). WaselERP يفتقر لنموذج **Device/Station profiles** (مثلاً ربط محطة POS بطابعة، قالب إيصال، درج، كاميرا/ماسح، إلخ).
2. **إدارة الطباعة متعددة القنوات**: إيصال عميل، مطبخ، باركود/ملصقات، A4 — بدون مركز إعداد وتوجيه موحد.
3. **النسخ الاحتياطي/الاستعادة كقدرة منتج**: موجود كفجوة صريحة في الخطة (**P7**) ويؤكدها الدليل.
4. **المرفقات**: فجوة صريحة (**P7**).
5. **قنوات الإشعار والتكامل (بريد/SMS/واتساب)**: متفرقة بين **P7** (إشعارات/تكاملات عامة) و**Gate 7/P9** (واتساب/AI).
6. **تكاملات الأجهزة** (ميزان، شاشة سعر، مودم، بصمة): تتطلب عادةً **Agent/جسر محلي** أو خدمات إضافية؛ خارج قدرات الويب وحده.
7. **سياسات تشغيل POS قابلة للتهيئة**: جزء كبير منها تحسينات فوق **Gate 3** المغلق.

## 4) الربط بخطة العمل (EEYES-STEPS / EZEES-COVERAGE)

| بند/مجال من settings-advanced | بوابة/مرحلة في الخطة | الحالة الحالية بالخطة | التوصية |
|---|---|---|---|
| الطباعة (قوالب، نسخ، توجيه كاشير/مطبخ، A4 رسمي) + إعدادات جهاز/محطة | **P7 — الإعدادات والأدوات** + متبقيات Print Agent (AGENTS) | P7 ⬜؛ Print Agent يحتاج اختبار ميداني ودعم A4 وتثبيت خدمة | إدراج "مركز إعدادات الطباعة والمحطات" ضمن حزمة P7، مع توسيع Print Agent تدريجيًا |
| طباعة الباركود/الملصقات المتقدمة (مقاسات، قوالب، مصدر الباركود) | **Gate 4** (ملصقات UI ✅) + **P7** | Gate 4 ✅ مغلق؛ المتقدم غير مُفصّل | مهام تحسين ضمن P7 (لا تعيد فتح Gate 4 إلا بتوسعة نطاق رسمية) |
| النسخ الاحتياطي/الاستعادة/جدولة/سحابي | **P7** | ⬜ | أولوية عالية في P7 (متطلب تشغيلي وأمني) |
| مزامنة OnLine/OffLine بقواعد محلية للفروع | لا يوجد كبند مطابق؛ لدينا offline queue مختلف | — | **خارج النطاق** كنمط Ezees؛ أي مزامنة قواعد تتطلب قرار معماري مستقل |
| تخصيص POS (لمس، افتراضيات دفع/طباعة، سياسات إدخال) | تحسينات بعد **Gate 3** + جزء من **P7** | Gate 3 ✅ | تجميع كـ "تحسينات إعدادات POS" في باك لوج P7/تشغيلي |
| أجهزة POS (شاشة سعر/مودم/ميزان بصيغة COM) | — | — | **مبادرة تكامل أجهزة** (Agent) خارج P0–P7؛ تقدير منفصل |
| سياسات السلف/البصمة/أتمتة حضور ورواتب متقدمة | **P6** (وتفاصيل EZEES-COVERAGE) | Gate 6 أساس ✅ لكن متبقيات HR موجودة | استكمال بنود P6 قبل/ضمن أي توسعة إعدادات HR متقدمة |
| المرفقات | **P7** | ⬜ | ضمن P7 كما هو مخطط |
| Email/SMS | **P7** (إشعارات/تكاملات) أو تكاملات موازية | ⬜ | تحديد مزودين ونطاق (تشغيلي vs تسويقي) |
| واتساب وقوالب ورسائل تلقائية | **Gate 7 / P9** | ⬜ | ربط مباشر بخطة AI/واتساب |
| المظهر (ثيم/خطوط) | **P7** (تجربة استخدام) بشكل جزئي | ⬜ | أولوية منخفضة مقارنة بالوظائف الحرجة |
| التصنيع | خارج البوابات الحالية | — | باك لوج متخصص عند الطلب |
| ExtraModule (إخفاء وحدات بالجهاز) | بديل: **RBAC/Scopes** ضمن **P7** | صلاحيات موجودة، scopes دقيقة متبقية | تفضيل نموذج الصلاحيات على "كود دعم إخفاء محلي" |
| المستخلصات/المقاولات | **P8** | ⬜ | فقط بطلب سوقي |
| إعداد اتصال DB/إعداد SQL Server عن بعد/رسائلها | غير منطبق معماريًا | — | **استبعاد** من منتج WaselERP الويب؛ توثيق تشغيلي بدلاً من UI عميل |

**ملاءمة مع "التالي" في `docs/EEYES-STEPS.md`:** الخطة الحالية تضع التالي على **Gate 7 (ETA ربط حقيقي + AI/واتساب)**. فجوات `settings-advanced` القابلة للتطبيق تتوزع أساسًا على **P7** (أدوات/إعدادات/نسخ احتياطي/مرفقات/طباعة/تجربة استخدام) وامتدادات **P6**، مع جزء تكاملي يلامس **P9/واتساب** — أي أنها **باك لوج مكمل** وليس بديلاً عن Gate 7 ما لم تُعاد الأولويات.

## 6) قرارات مطلوبة قبل التنفيذ

1. **نموذج "إعدادات الجهاز" في الويب/PWA:** هل تُدار كـ Station profile في الخادم (موصى به للاتساق) أم إعدادات محلية بالمتصفح/الوكيل لكل جهاز؟
2. **نطاق Print Agent:** هل يظل ESC/POS أساسيًا مع إضافة قوالب A4/توجيه متعدد، أم يُعاد تصميم طبقة الطباعة؟
3. **النسخ الاحتياطي:** مسؤولية تشغيلية (DBA/Infra) فقط أم ميزة داخل المنتج بواجهة وجدولة؟
4. **واتساب:** ضمن Gate 7/AI أم تكامل إشعارات مستقل مبكر؟
5. **تكاملات الأجهزة (بصمة/ميزان/شاشة سعر):** هل هناك طلب سوقي يبرر بناء Agent/Drivers؟

## 7) خلاصة الربط بالخطة

- مرجع `settings-advanced` **لا يغيّر** حالة البوابات المغلقة (Gate 0–6 أساسًا، Gate 4–5 مغلقة)، لكنه يوضح أن **P7** ما زال يحمل جزءًا كبيرًا من "نضج الإعدادات والأدوات" (طباعة متقدمة، نسخ احتياطي/استعادة، مرفقات، إشعارات، تقييد/سياسات).
- جزء من البنود **غير قابل للنقل** إلى WaselERP بسبب اختلاف المعمارية (سطح مكتب + SQL Server + مزامنة قواعد محلية + أجهزة COM) ويجب توثيقه كـ **خارج النطاق/مستبدل بآلية مختلفة**.
- الأولوية العملية المقترحة: **إغلاق/تنفيذ P7 تدريجيًا** (خاصة النسخ الاحتياطي والمرفقات وإعدادات الطباعة/المحطات) بالتوازي مع توجه الخطة الحالي نحو **Gate 7** عند توفر متطلبات ETA/التكاملات.
