# E1 — Bank Reconciliation (المطابقة البنكية) — مواصفات تنفيذية

> **الحالة:** تصميم فقط — غير مُنفّذة في الكود
> **الأولوية:** متوسطة · **التعقيد:** متوسطة · **الأثر المحاسبي:** مباشر

---

## 1) المشكلة الحالية

لا يوجد في النظام أي تمثيل لمكشف حساب البنك مقابل كشف البنك الورقي:

- `cash_accounts` (type=2) يمثل **رصيد البنك الدفتري** فقط.
- `gl_accounts` 1102 (النقدية بالبنك) يعكس نفس القيمة (GL لأنه مربوط بـ `gl_account_id`).
- لا يوجد جدول لـ "حركة بنكية غير مرفقة بقيد" ولا لـ "فروقات بين كشف البنك ورصيد دفتر الذات".
- كشف البنك يتضمن: رسوم بنكية، تحويلات مجهولة، شيكات معلقة، مرتدات — لا شيء منها يُعالج آليًا.

## 2) الهدف

نموذج محاسبي كامل للمطابقة:

```
دفتر البنك (مورد/عميل)  ↔  كشف البنك الورقي  →  مسير المطابقة  →  قيد الفروقات (إن وجد)
```

## 3) نموذج الأحداث

| نوع الحساب البنكي الموصى به | الحدث المتوقع | الوصف |
|---|---|---|
| دفتر (Bank Ledger) | فواتير مشتريات/مبيعات وايداعات | تلقائي |
| كشف (Bank Statement) | فواتير/رسوم/شيكات | إدخال يدوي أو استيراد |
| مسير (Reconciliation Run) | مطابقة (manual / auto by rule) | يحدد الفروقات |
| فرق (Variance Rule) | قيد تلقائي للاختلافات المتكررة | سلوك قابل للضبط |

## 4) التغييرات على قاعدة البيانات

```sql
-- E1.1 — جدول مستقل لكشف البنك (الحالة الورقية)
CREATE TABLE IF NOT EXISTS bank_statement_lines (
    line_id            bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    bank_account_id    integer NOT NULL REFERENCES cash_accounts(cash_account_id),
    branch_id          integer NOT NULL REFERENCES branches(branch_id),
    statement_date     date NOT NULL,
    value_date         date,
    description        text NOT NULL,
    reference          varchar(60),
    -- موجب للإيداع/المستلمة من العميل، سالب للمصريفات/المدفوعة للمورد
    amount             numeric(18,2) NOT NULL,
    balance_after      numeric(18,2),
    matched_entry_id   bigint REFERENCES gl_entries(entry_id),
    status             smallint NOT NULL DEFAULT 1,   -- 1 unreconciled · 2 auto-matched · 3 manual-matched · 4 disputed
    import_batch_id    uuid,
    created_by         integer REFERENCES users(user_id),
    created_at         timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS ix_bank_statement_account_status ON bank_statement_lines(bank_account_id, status);
CREATE INDEX IF NOT EXISTS ix_bank_statement_date ON bank_statement_lines(bank_account_id, statement_date);
CREATE INDEX IF NOT EXISTS ix_bank_statement_batch ON bank_statement_lines(import_batch_id);

-- E1.2 — جدول الفروقات المسوّاة مع السبب والربط المحاسبي
CREATE TABLE IF NOT EXISTS bank_reconciliation_runs (
    run_id             integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    bank_account_id    integer NOT NULL REFERENCES cash_accounts(cash_account_id),
    branch_id          integer NOT NULL REFERENCES branches(branch_id),
    period_id          integer REFERENCES periods(period_id),
    run_date           date NOT NULL,
    book_balance       numeric(18,2) NOT NULL,
    statement_balance  numeric(18,2) NOT NULL,
    variance           numeric(18,2) NOT NULL,
    matched_count      integer NOT NULL DEFAULT 0,
    unmatched_count    integer NOT NULL DEFAULT 0,
    status             smallint NOT NULL DEFAULT 1,   -- 1 draft · 2 posted · 3 reopened
    journal_id         bigint REFERENCES gl_journals(journal_id),
    notes              text,
    created_by         integer NOT NULL REFERENCES users(user_id),
    created_at         timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS ix_bank_recon_branch_date ON bank_reconciliation_runs(branch_id, run_date);

-- E1.3 — قواعد المطابقة الآلية القابلة للضبط
CREATE TABLE IF NOT EXISTS bank_matching_rules (
    rule_id            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    branch_id          integer NOT NULL REFERENCES branches(branch_id),
    pattern            text NOT NULL,                  -- LIKE/regex على description
    counterparty_hint  text,                           -- اسم مستفيد/مورد
    expense_mapping_id integer REFERENCES gl_mappings(mapping_id) ON DELETE SET NULL,
    priority           integer NOT NULL DEFAULT 10,
    is_active          boolean NOT NULL DEFAULT true,
    created_at         timestamptz NOT NULL DEFAULT now()
);

-- E1.4 — علاقة تدقيق الرصيد بعد كل مسير
ALTER TABLE cash_accounts
    ADD COLUMN IF NOT EXISTS reconciled_balance numeric(18,2),
    ADD COLUMN IF NOT EXISTS last_reconciled_at timestamptz;
```

## 5) القيود المحاسبية المتوقعة

### 5.1 فرق رسوم بنكية يكتشفه كشف البنك (لا سددها دفتر البنك)
```
Dr  5107  مصروفات مالية      [الفرق]
Cr  1102  النقدية بالبنك     [الفرق]
```

### 5.2 شيك مرتد يكتشفه كشف البنك (في الدفتر ورد في الميزانية)
```
Dr  2101  ذمم الموردين      [الشيك]
Cr  1102  النقدية بالبنك    [الشيك]
```

### 5.3 إيداع مجهول من العميل كشف البنك
```
Cr  1102  النقدية بالبنك    [المبلغ]
Dr  1103  ذمم العملاء       [المبلغ]   -- بدل 4101 (إن كان لا يعرف من للعميل: 1106 أو 4104 بضغط)
```

### 5.4 مقابل
```
Dr  1102  النقدية بالبنك    [المبلغ]
Cr  xxxx               [المبلغ]   -- حسب rule المعرّفة
```

كل قيد يمر من `postJournal` العادي بقواعد `assertPeriodOpen` — إذا كانت الفترة مقفولة، لا يُنفّذ المسير.

## 6) الصلاحيات

| الدور | الصلاحية |
|---|---|
| محاسب (Accountant) | إنشاء/قراءة/طباعة كشف البنك والمسيرات |
| مدير النظام | حذف مسيرة (يحتوي GL journal) — `deleteGuard('bank-recon')` |
| كاشير | لا تصل لـ Bank Reconciliation إطلاقا |

## 7) قواعد التحقق

1. **التطابق الذاتي:** لا يمكن تجهيز مسير لبنك ليس له كشف lines غير مُطابقة.
2. **توافق العملات:** خط كشف لا بد أن يطابق `branch.currency_code`.
3. **نفس الفترة:** مسير لفرع+فترة يحق مقارنته فقط بخطوط كشف البنك الثنائية.
4. **إقفال الفترة:** حصر `periods.is_closed` → رفض أي مسير بتاريخ يقع داخل فترة مقفولة.
5. **إعادة الفتح:** مسير `posted` لا يُعدل، والمسألة = قيد عكسي (عكس تلقائي عند تغيير `status`).
6. **التطابق اليدوي:** اختيار line ↔ assertion يدوي → يولّد قيد تسوية مع تثبيت `matched_entry_id`.

## 8) الـ API

```
GET    /treasury/bank-accounts                   — الحسابات البنكية النوع 2
POST   /treasury/bank-statements/import           — استيراد CSV/XLSX لكشف البنك
GET    /treasury/bank-statements?accountId=X&from=&to=   — استعراض الكشف
POST   /treasury/bank-statements/lines/:id/match   — تطابق يدوي (line ↔ entryId)
POST   /treasury/bank-statements/lines/:id/unmatch
GET    /treasury/reconciliation/:bankAccountId/runs — كل المسيرات
POST   /treasury/reconciliation/runs                 — إنشاء مسيرة (book/stmt/variance)
POST   /treasury/reconciliation/runs/:id/post        — ترحيل + قيود تلقائية
GET    /treasury/reconciliation/runs/:id/report      — PDF/Excel (مسك كشف البنك)
GET    /treasury/reconciliation/history              — طرف للتوقع والمقارنة
```

## 9) التقارير

1. **كشف المطابقة الشهرية** — دفتر مقابل كشف البنك، الفروقات بالتفصيل، معايير الإقفال.
2. **قائمة الرسوم البنكية المعلقة** — يحتاج قيد تلقائي (Dr 5107 / Cr 1102).
3. **قائمة الشيكات المرتدة** — Dr/Cr مع التنبيه للإدارة.
4. **كشف الفروقات المتكررة** — Rule suggestions (اقتراح قاعدة من 3+ حالات متشابهات).

## 10) الاختبارات الآلية (سيُستقى مسارات P2 assertions)

| الاختبار | ما يتحقق منه |
|---|---|
| Import statement → lines created | استيراد كشف بمبلغ معروف يظهر نفسه في `bank_statement_lines` |
| Auto-match by reference | مطابقة بـ `reference` يملأ `matched_entry_id` و`status=2` |
| Manual match creates journal | مسيرة with variance → Dr 5107 / Cr 1102 لرسم البنك نفسه |
| Close-period guard | مسيرة بتاريخ 2026-10 بعد إقفال أكتوبر ← 400 مع رسالة الفترة المقفولة |
| Reopening a posted run forbidden | إعادة `posted` → جدول فارغ + message واضحة |
| Permission guard | كاشير → 403 على كل `bank-statements` |
| Variance accounting | كشف به فرق 11 (رسوم + دفعة) ← قيدان مختلفان على 5107/1102 |

## 11) خطوات التنفيذ (رحلة قصيرة — 8 خطوات فقط)

1. تطبيق DDL (E1.1–E1.4) على قاعدة CI أولًا ثم الهجينة (`tools/pg/migrate-all.js`).
2. `bank_matching_rules` seed: 3 قواعد (سداد عميل / شيك / رسوم بنكية).
3. import-statement helper: دالة اختيار "قيمة كشف البنك" ناقصة بقيم قاعدة ذاتية يستخدم token.
4. `/reconciliation/runs` POST → إنشاء run بمجرد معرفة book/stmt → حساب variance تفصيلي.
5. `/reconciliation/runs/:id/post` — مفاتيح 5107/1102 وبنود `bank_statement_lines.matched_entry_id`.
6. UI سك حـ 4 توابات تحت `/accounting` المالي: دفتر / كشف / مسير / التقرير.
7. **بدون touch إنتاج** — استخدم نفس نمط مخزن محلي، ثم CI smoke with @X.
8. توثيق in `GL_JOURNALS` : نوع `bank_recon` مرفق بـ `reference` = run_id.

## 12) ما الذي لا أفعله

- لا أنشئ أي شيء على فرع الإنتاج (`wasel-prod`) ولا lagoon none.
- لا أتدخل في `pos` / `purchases` / `sales` flows.
- لا أفترض قاعدة auto-match صحيحة بدون 3 تكرارات حقيقية.
- لا أحذف أي `bank_statement_lines` لأي سبب — الحل audit trail دائمًا.
