# تحليل فجوات «إعدادات البرنامج» (settings.txt) وربطه بخطة العمل

> **المصدر:** `docs/ezees-guide/settings.txt` و `docs/ezees-guide/settings.html` (دليل Ezees ERP — "إعدادات البرنامج: شرح كل تبويبات شاشة الإعدادات"، آخر تحديث بالمصدر: 2026-10-10).
>
> **مقارنة مع:** حالة WaselERP الحالية (Next.js 14 static/PWA + NestJS 10 + PostgreSQL + Print Agent محلي + ETA/ZATCA) وملفات الخطة: `docs/EEYES-STEPS.md`, `docs/EZEES-COVERAGE.md`, `docs/ARCHITECTURE.md`, `AGENTS.md`, `docs/GAP-SETTINGS-ADVANCED.md` (التحليل الشقيق المتقدم، مكتمل 2026-11-14).
>
> **ملاحظة تنفيذية (2026-11-14):** شاشة «إعدادات النظام» (`apps/web/app/admin/page.tsx` — تبويب settings) كانت تعرض مفاتيح `app_settings` الخام بأسمائها التقنية؛ تمت إعادة تصميمها في نفس هذا العمل لتعرض مجموعات منطقيات (الشركة والفاتورة / الضرائب / المخزون / نقطة البيع / المحاسبة) مع حقول عربية وأوصاف وحقول تبديل للقيم البوليانية.

---

## 1) ملخص تنفيذي

| المؤشر | النتيجة |
|---|---|
| أقسام الدليل | 6 تبويبات (عامة، فواتير، فواتير إضافية، ضرائب، دورة المبيعات والمشتريات، حفظ/أين تُحفظ) + رسائل وأسئلة شائعة |
| منطبق على WaselERP | **≈20–30%** — أساس الإعدادات العامة/الضريبية موجود (`app_settings` + مفاتيح مُستهلكة فعليًا)، والترحيل المحاسبي/المخزني يعمل |
| موجود بصيغة مختلفة | **≈15–25%** — branch-scope في كل استعلام، صلاحيات RBAC، إلزام الوردية، قوائم أسعار حسب العميل، scope مخازن/صناديق (P7) |
| غير موجود/غير منطبق معماريًا (سطح مكتب) | **≈45–60%** — تبويبات الطباعة التفصيلية، إعدادات لكل جهاز، Load Default، اللغة/المظهر لكل جهاز، أوامر الدورة القابلة للتبديل من الواجهة، أصناف بدون سعر كخيار، سرية العملة لكل بيئة |

**الخلاصة:** مرجع `settings.txt` موجه لمنتج سطح مكتب عربي كلاسيكي (Ezees/SQL Server + سيناريوهات محاسبية بالأساس مصرية). في WaselERP: ما يمكن نقله "كإعداد DB مع منطق API" أُنجز أو يُستكمل ضمن **P7 — الإعدادات والأدوات**؛ أما ما هو "خيار لكل جهاز" فيُعاد تعريفه كتفضيلات واجهة/محطة أو يُستبعد مع توثيق؛ ولا يوجد حتى الآن **نموذج "إعدادات الفروع"** إلا للـ POS (`pos_settings`).

### 2.4 دورة المبيعات والمشتريات

| بند الدليل | الحالة في WaselERP | الفجوة | الربط بالخطة |
|---|---|---|---|
| امر → فاتورة (الترحيل المباشر) | ✅ الوضع الفعلي دائمًا: الفواتير تخصم/تضيف للمخزون فورًا | لا يوجد مفتاح؛ وهو المطلوب لعمل WaselERP الأساسي |
| امر → اذن مخزن → فاتورة | 🟡 جزئي — أذون مخزن (P4.2) والتحويل غير المباشر (P4.3) موجودة ومكتملة، لكن لا يوجد "دورة" قابلة للمفاضلة تُفرض من الواجهة (مبنى إلزام أذون) | `SalesCycleMode` غير موجود | **P7** (كبير نسبيًا؛ مؤثر على Khozain) |
| امر → فاتورة → اذن مخزن | 🟡 جزئي — بنفس الشكل، غير موجود كاختيار | — | **P7** |
| ترحيل الفواتير تلقائي (يُقفَّل مع الدورة الثانية/الثالثة) | ✅ دائمًا (لا يوجد مفتاح) | عدم وجود مفتاح يجعل "المخزن أولًا" مشروعًا إضافيًا | **P7** |

## 3) فجوات عرضية (Cross-cutting)

1. **نموذج "إعدادات الفرع" مقابل "نظام فقط"**: WaselERP يستخدم `app_settings` (global) + `pos_settings` (per-branch). لا يوجد `branch_settings` عام، ولا يوجد "جهاز/محطة". أي إعداد يخص الاستجابة لإعدادات الفرع يحتاج نموذجًا جديدًا.
2. **صلاحيات "إعدادات ج دون أثر"**: لدينا `settings.manage` (حفظ الإعدادات) و`users.manage`. الخلاصة: لا يوجد "بت إعدادات مقيد للقراءة فقط".
3. **غياب مفتاح "إخفاء القسم" و"كتمان البيانات"**: ملائم في سطح مكتب/مرخّص فقط.
4. **لا يوجد مفهوم "فترة مالية تمنع حفظ الإعدادات"** لأن الإعدادات عامة، لكن هذا مطبق للترحيل فقط — توثيق مطلوب.
5. **مفاتيح `app_settings` المستهلكة فعليًا يجب أن تكون موثقة** بدل ما تُعرض تقنيًا — وهذا ما بُدئ به في هذا العمل بإبرازها في أقسام + تعطيل المقاليع الخام في "مفاتيح أخرى".

## 6) قرارات مطلوبة قبل التنفيذ

1. **أين تُحفظ إعدادات الفرع؟** (جدول جديد `branch_settings` / توسيع `app_settings` بمفتاح `BranchID` منفصل مع قيمة NULL؟) — التوصية: جدول مستقل `branch_settings`.
2. **مَن يقرأ "إعدادات الجهاز"؟** إذا لزم تخصيص طُبع لكل محطة POS (على غرار Print Agent)، فمن مسؤولية الـ Agent/المتصفح — لا في الويب.
3. **هل تصبح مفاتيح `app_settings` معتمدة مع castات صريحة؟** التوصية: Typing module `common/settings.ts` موجود وسيظل هكذا، والمفاتيح الجديدة تمر منه.
4. **الوحدة "دورة المبيعات/المشتريات" القابلة للتبديل:** هل تُبنى الآن (P7) أم تُترك كـ "مبكر ولا يضيف قيمة تشغيلية" (حتى يُطلب سوقيًا)؟
5. **ETA/ZATCA "إرسال تلقائي بعد الحفظ":** هل يُضاف كإعداد "على الفاتورة" أم يكون ضمن إعدادات العميل المستقل؟

## 7) خلاصة الربط بالخطة

- حقول `app_settings` التي تعمل فعليًا (`AllowNegativeStock`, `RequireCashierShift`, `EnableGLPosting`, `DefaultVatPct`, `CompanyName`, `CompanyPhone`, `CompanyAddress`, `TaxNumber`, `InvoiceFooter`) **ليس لها واجهات عربية** قبل هذا العمل؛ تم إعادة عرضها في تبويب «إعدادات النظام» ضمن مجموعات عربية مع أوصاف وحقول تبديل، مع وضع المفاتيح غير الموثقة تحت قسم "مفاتيح أخرى" مع التنبيه.
- بضعة بنود من الدليل **لا يمكن نقلها** إلى WaselERP لوجستيًا (سطح مكتب، SQL Server، أوفلاين بقواعد محلية، أجهزة COM) — مستبعدة مع التوثيق في `GAP-SETTINGS-ADVANCED.md` §2.12 وتُستبعد هنا أيضًا.
- أهم نقطة فجوة فريدة في settings.txt: **«اعدادات الفرع»** (بينما app_settings global) + **"استرجاع الافتراضيات» + «مفاتيح دورة الفاتورة/البيع»** — وهي البنود الوحيدة القابلة للتقديم العالي.
- **الأولوية العملية:** إغلاق فجوات «إعدادات البرنامج» القابلة للتطبيق ضمن **P7** (خصوصًا: إعدادات الفرع، Load Default، مفاتيح دورة الفاتورة)، ولا تُعدّّل البوابات المغلقة (Gate 0-6)، وتُترك إعدادات الأجهزة/المتصفح للتشغيل المحلي مع Print Agent.
