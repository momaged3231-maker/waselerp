# تحليل تغطية دليل Ezees ERP مقابل WaselERP

> **الغرض:** الإجابة على سؤال واحد: «هل كل ما في دليل Ezees ERP موجود عندنا؟ وإن لم يكن، ما الذي يجب بناؤه بالترتيب؟»
>
> **المصدر:** دليل استخدام Ezees ERP — `https://help.tebalink.com` (آخر تحديث بالدليل: 8 أكتوبر 2026) — **65 صفحة وظيفية** تم تنزيلها وقراءتها، بالإضافة إلى 109 مقالًا محاسبيًا (لم تُحلَّل مقالاتيًا، لكن عناوينها استُخدمت في تحديد نطاق التقارير والمفاهيم).
>
> **المرجع الداخلي:** `AGENTS.md` · `docs/ARCHITECTURE.md` · `docs/HANDOVER.md` · `docs/REFERENCE-ANALYSIS.md`
>
> **تاريخ التحليل:** 2026-11-13
>
> **حدود التحليل:** تحليل ثابت (قراءة كود + مخطط DB + مقارنة سلوك). **لم يُشغَّل `npm test`** لأن بيئة التحليل لا تحتوي `node_modules` ولا PostgreSQL يعمل. كل ما هو مكتوب «موجود» مبني على قراءة الكود وليس على تنفيذ فعلي.

## 1) الخلاصة التنفيذية

| المؤشر | النتيجة |
|---|---|
| شاشات/مواضيع الدليل | 65 |
| موجودة بالكامل (مطابقة 100%) | **0** |
| موجودة جزئيًا (الأساس موجود والنواقص جوهرية) | **24** (37%) |
| غير موجودة أصلًا | **41** (63%) |
| تغطية النواة التجارية (بيع/شراء/مخزون/خزينة/تقارير أساسية) | **~55–60%** |
| تغطية الدليل الكامل (بما فيه المحاسبة والأنظمة المتخصصة والمساعد الذكي) | **~30%** |

**أهم 5 نتائج:**

1. **لا توجد محاسبة عامة (GL) إطلاقًا.** لا شجرة حسابات، ولا قيود يومية، ولا سندات قبض/صرف، ولا شيكات، ولا مراكز تكلفة، ولا عملات. كل التقارير المالية في Ezees (ميزان المراجعة، الأرباح والخسائر، الميزانية، الإقرار الضريبي، دفتر الأستاذ، أعمار الديون) **غير ممكنة** حاليًا. هذه ليست «ميزة ناقصة» بل **أساس** يترتب عليه 6 شاشات + 3 مجموعات تقارير.
2. **دورة البيع/الشراء ناقصة من المنتصف:** لا عروض أسعار، ولا أوامر بيع/شراء، ولا حجز مخزون، ولا شحن/تسليم، ولا ربط المرتجع بالفاتورة الأصلية، ولا قوائم أسعار، ولا كوبونات/عروض هدايا.
3. **نقطة البيع أبسط من Ezees بفارق كبير:** لا ورديات إلزامية، لا تعليق فواتير، لا مرتجع من الكاشير، لا طرق دفع متعددة (فيزا/بنك/محفظة)، لا مطاعم/طاولات/مطبخ، لا أنواع أسعار (جملة/نصف جملة)، لا عملاء توصيل/سائقين.
4. **توجد أخطاء حقيقية في النواة تمنع التشغيل الفعلي** — أهمها أن **دور «كاشير» لا يستطيع إنشاء فاتورة بيع** بسبب شرط صلاحيات AND، وأن **تسوية المخزون السالبة تزيد الرصيد بدل أن تنقصه**، وأن **فاتورة الشراء لا تُحدّث متوسط التكلفة**. التفاصيل في §4.
5. **التقارير:** عندنا **7 تقارير**، وفي Ezees ما يزيد على **80 تقريرًا** موزعة على 5 مجموعات. الفجوة هنا ليست في العدد فقط بل في **غياب محرك تقارير** (فلاتر، تصدير Excel، Pivot، معاينة/طباعة، تقارير مخصصة).

## 2) ما هو منجز فعليًا (بالدليل)

هذا ليس تقليلًا من الشغل الموجود — الأساس جيد ومتماسك معماريًا. لكنه **نواة تشغيلية** وليس ERP مكتمل.

| المجال | الموجود | الدليل في الكود |
|---|---|---|
| المصادقة والصلاحيات | JWT + Refresh + scrypt + 23 صلاحية + 5 أدوار + عزل فروع | `common/security.ts` · `cli/seed.ts` |
| الفواتير | 4 أنواع (بيع/شراء/مرتجع بيع/مرتجع شراء)، خصم سطر ورأس، ضريبة، نقدي/آجل/مختلط، إلغاء بعكس المخزون، idempotency | `modules/sales/sales.slice.ts` |
| المخزون | دفتر حركات موحّد، تحويل، جرد، تسوية، متوسط تكلفة، أرصدة | `common/stock.ts` · `modules/inventory` |
| الوحدات المتعددة | معامل تحويل + سعر بيع/شراء لكل وحدة | `item_units` · `POST /items/:id/units` |
| الخزينة | حسابات، فئات، حركات، تحويل بين حسابات، ورديات (API فقط) | `modules/treasury` |
| العملاء والموردون | بطاقة + حد ائتمان (حقل) + كشف حساب API + رصيد افتتاحي | `modules/parties` |
| التقسيط | خطة + جدول أقساط + سداد + مستحقات | `modules/installments` |
| الموارد البشرية | موظفون، حضور يدوي، كشف رواتب بسيط + صرف | `modules/hr` |
| ZATCA | XML UBL 2.1 + QR TLV + ختم ECDSA/RSA + حفظ + إرسال clearance/reporting | `modules/zatca` |
| التقارير | 7 تقارير (لوحة، مبيعات، أصناف، مخزون، أرصدة، خزينة، ساعات) | `modules/reports` |
| الإعدادات | key/value (7 مفاتيح) + مستخدمون/فروع/أدوار + سجل عمليات | `modules/admin` |
| الواجهة | 12 شاشة RTL + PWA + أوفلاين (فواتير فقط) + SSE | `apps/web` |
| الطباعة | وكيل محلي ESC/POS + درج نقدية + طابعات شبكة | `apps/print-agent` |

1. `resolvePrice` كان يستخدم `$3` لحد الفرع و `$3` للتاريخ معًا → `cannot cast type integer to date`. أُعيد ترقيم الباراميترات.
2. `CREATE INDEX ... price_lists(branch_id)` كان يسبق إضافة العمود على قواعد قائمة → فشل المخطط. نُقل ترحيل الأعمدة **قبل** الفهارس.
3. `ON CONFLICT (code)` مع فهرس جزئي (`WHERE code IS NOT NULL`) كان يُسقط نواة Postgres داخل PGlite → الفهرس أصبح غير جزئي + البذر يستخدم SELECT/UPDATE بدل ON CONFLICT.
4. `quotation_date`/`order_date` أعمدة NOT NULL مع DEFAULT لكن الكود كان يرسل NULL → `COALESCE($n::date, CURRENT_DATE)`.
5. الاستيراد الدائري (sales ⇄ documents) كان سيكسر حقن الاعتماديات → وحدة المبيعات انتقلت لملف `sales.module.ts` مستقل.
6. **أعمدة `bigint` كانت ترجع strings** بينما `integer` ترجع أرقامًا → عدم اتساق الـ API (وأخطاء مقارنة في الواجهة). أُضيف `types.setTypeParser(20, Number)` في `DatabaseService`.
7. ترتيب حذف الجداول في `reset-dev-data.sql` كان يخالف الـ FK (شيكات قبل سندات قبل قيود قبل فواتير) → صُحّح.
8. `quotations`/`orders`/`shipments`/`invoice_allocations` كانت تُنشأ قبل جداول تعتمد عليها → نُقلت لآخر المخطط.

**متبقٍ في P2:** تعديل فاتورة مخصَّصة لسند (يحتاج فك التخصيص أولًا) · رسوم التوصيل تُضاف لفاتورة مستقلة · إرجاع الكوبون عند إلغاء الفاتورة · عروض هدايا بسعر باقة (bundle price) بدل الهدية المجانية.

## 5) الفجوات البنيوية (ما يجب بناؤه، وليس فقط إضافته)

### 5.1 محرك المحاسبة العامة — الأساس الغائب
كل ما في Ezees من سندات وشيكات ومراكز تكلفة وتقارير مالية وقيد تلقائي للرواتب والمخزون **يعتمد على GL**. البديل الحالي (`ledger_entries` + `cash_transactions`) هو دفتر مساعد للعملاء والخزينة فقط، ولا يصلح لإنتاج:
- ميزان مراجعة متوازن
- قوائم مالية
- إقرار ضريبي
- تكلفة بضاعة مباعة بالحسابات

**المطلوب:** `chart_of_accounts` · `journal_entries` + `journal_lines` · `account_mappings` (حسابات افتراضية) · `cost_centers` · `currencies` + `exchange_rates` · `checks` · `vouchers` · ترحيل تلقائي من الفواتير/الخزينة/المخزون/الرواتب · إقفال فترات · تقارير مالية.

### 5.2 محرك المستندات (Document Engine)
Ezees مبني على «مستند + حالة + اعتماد + ترحيل». عندنا كل شيء يُحفظ مباشرة كنهائي. المطلوب:
- حالة المستند: مسودة → معتمد → مرحّل → ملغي
- عكس الحركات بقيد عكسي وليس تعديل
- ربط المستندات ببعضها (`parent_invoice_id`, `source_order_id`, `receipt_id`)
- ترقيم موحّد لكل نوع/فرع/سنة
- مرفقات وتدقيق لكل مستند

### 5.3 محرك التقارير
بدل 7 استعلامات ثابتة: تعريف تقرير + فلاتر + أعمدة + إجماليات + تصدير Excel/PDF + Pivot + طباعة. هذا يفتح الباب لـ 80+ تقريرًا بأقل كود.

### 5.4 محرك الأسعار والعروض
`price_lists` موجودة وغير مستخدمة. المطلوب: أنواع أسعار (نقدي/جملة/نصف جملة)، قوائم لكل عميل/فرع، كوبونات، خصومات فئات، عروض هدايا، تعديل جماعي، تاريخ أسعار.

### 5.5 محرك الصلاحيات الدقيقة
الصلاحيات الحالية 23 على مستوى الوحدة. Ezees تفرّق بين: إظهار الربح، تجاوز الخصم، تعديل السعر، فتح مستند، تقييد مخزن/صندوق/مركز تكلفة، نسخ صلاحيات. المطلوب توسيع `permissions` + `user_scopes`.

## 7) قرارات مطلوبة قبل البدء

1. **السوق المستهدف:** مصر (ETA إلزامية) أم السعودية (ZATCA) أم الاثنان؟ هذا يحدد أولوية P9.
2. **نوع النشاط:** تجزئة/سوبر ماركت أم مطاعم أم توزيع أم مقاولات/عقارات؟ لا يمكن بناء كل الأنظمة المتخصصة بجودة عالية في نفس الوقت.
3. **المحاسبة:** هل ننفذ GL كامل (توصية قوية) أم نكتفي بتقارير تشغيلية مبسطة؟ أي حل وسط سيظل عاجزًا عن الإقرار الضريبي والميزانية.
4. **التوافق مع Ezees:** هل الهدف «نفس الشاشات» أم «نفس القدرات بتجربة أنظف»؟ الثانية أسرع وأفضل تقنيًا.
5. **المساعد الذكي/واتساب:** الآن أم بعد استقرار النواة؟ (يعتمد على ميزة بيعية وليس على تشغيل).
6. **الترخيص:** هل النظام سيكون SaaS متعدد الشركات أم نشرًا مستقلًا لكل عميل؟ (يؤثر على المخطط والصلاحيات والنسخ الاحتياطي).
