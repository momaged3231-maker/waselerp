# E6 — الإقفال الشهري الآلي (Automated Monthly Closing) — مواصفات تنفيذية

> **الحالة:** تصميم فقط — `periods` موجود بـ `is_closed` + قيد يدوي `manual periods`، لا ترحيل حساب ودخلي تلقائي
> **الأولوية:** عالية · **التعقيد:** متوسطة · **الأثر المحاسبي:** `3103 الأرباح المحتجزة` فقط + تحصين كل حساب بالمخطط

---

## 0) ما هو موجود فعليًا في الكود الآن

| البند | يوجد؟ | التفصيل |
|---|---|---|
| جدول `periods` مع `is_closed` + `branch_id` | ✅ | الحدود |
| `assertPeriodOpen(branchId, date)` | ✅ | يمنع أي ترحيل بالفترة المغلقة |
| `/accounting/periods/:id/close` و `/reopen` | ✅ | يدوي فقط، لا حساب ودخلي |
| `/accounting/periods/:id` (update meta) | ✅ | يدوي |
| `periods.is_closed` + المستندات مربوطة بـ `period_id` | ✅ | cascade على الفواتير و gl_journals |
| أي endpoint `nextPeriod`/`closeMonth`/`closingEntry` | ❌ | لا يوجد |
| حساب `3103 الأرباح المحتجزة` | ✅ | حساب GL بالخريطة `RETAINED_EARNINGS` |
| آلية ترحيل أنواع الحسابات (type 4 إيرادات) | ❌ | لا يوجد
| آلية ترحيل أنواع الحسابات (type 5 مصروفات) | ❌ | لا يوجد
| تقرير به مراجع من الدخل | ✅ | في /reports/general-ledger |
| دفتر تأشير الدورة المنتهية | ✅ | آخر عام في UI، يقفل`/suspend` |

## 1) الهدف

1. **نهاية يوم / نهاية شهر / نهاية سنة**: حساب الربح/الخسارة للفترة تلقائيًا (صافي كل type 4 − صافي كل type 5)
2. **ترحيل النتيجة إلى الأرباح المحتجزة 3103**: قيد عكسي واحد باعتماد `assertPeriodOpen`
3. **إقفال آلية «أي قيد آخر»**: بعد الإقفال، تُرفض أي فترة مفتوحة بهذه الأداء (مثلاً 2026-10-31 → 2026-11-30 تلقائيًا إن لم تكن مفتوحة)
4. **إقفال الفترة السابقة محمية `periods.closed_by = user`** — لا تتجاوزي الـuser admin rule
5. **توثيق الأداء** بملف Excel/PDF بـ Machinery fortnight

## 2) نموذج الأحداث

| الحدث | الجدول/الحركة | المعنى |
|---|---|---|
| pre-close check | فحص حسابات + فترة صالحة + لا بها pending | نقطة عبور |
| closing entry | قيد فردي يدوي في journal + retain | لا استئناف |
| سنة جديدة | Query `nextPeriod` | يسمح بتكبير الفترة بخطوة واحدة فقط |
| إعادة فتح | `reopen` (موجود) | فقط قرار مدير النظام |
| pre-close preview | قائمة التحقق المسبق | تحليل قبل يعمل، لا يكرر |

## 3) التغييرات على قاعدة البيانات

```sql
ALTER TABLE periods
    ADD COLUMN IF NOT EXISTS closing_entry_id bigint REFERENCES gl_journals(journal_id),
    ADD COLUMN IF NOT EXISTS net_income numeric(18,2);

CREATE TABLE IF NOT EXISTS period_close_checks (
    check_id              integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    period_id             integer NOT NULL REFERENCES periods(period_id),
    branch_id             integer NOT NULL REFERENCES branches(branch_id),
    check_code            varchar(60) NOT NULL,                    -- 'balance_verified', 'open_documents', 'pending_vouchers', 'shift_open'
    check_label           text NOT NULL,
    status                smallint NOT NULL DEFAULT 1,              -- 1 pending · 2 passed · 3 failed · 4 bypassed
    details               text,
    checked_at            timestamptz,
    resolved_by           integer REFERENCES users(user_id)
);

CREATE INDEX IF NOT EXISTS ix_period_close_checks_period ON period_close_checks(period_id);
```

## 4) القيود المحاسبية المتوقعة

### 4.1 — قيد الإقفال الإنتاج مزدوج (إرادات/مصروفات تصفر)

```
Dr  4101..4106..4107.. كل حسابات النوع 4 بكامل رصيدها الدائن (إغلاقها)
Cr  3103  الأرباح المحتجزة     [صافي الإيرادات − صافي المصروفات]
```

```
Dr  3103  الأرباح المحتجزة     [إجمالي المصروفات − إجمالي الإيرادات] (النتيجة سالبة)
Cr  5101..5103..5104..5106..5108..5109..5110..5111..5112.. كل حسابات النوع 5 بكامل رصيدها المدين (إغلاقها)
```

بقيدان اثنان منفصلان هما الأفضل M-ثنائيتي الأداء (متوازنة، عكس، مالية).
مطلوب أن يكون الـ journal author واضحًا: `sourceType='period_close'` مع `description` يتضمن الاسم والفترة.

## 5) الصلاحيات

| الدور | الصلاحية |
|---|---|
| مدير النظام | إغلاق/فتح فترة فقط (لتفادي الإقفال الخاطئ) — `RequirePermissions('accounting.close')` |
| محاسب عام | Pre-run preview فقط، لا confirm |
| كاشير | لا تصل لـ Period إغلاق |
| غير المستخدمين | كل API تبقى anonymous تستخدم admin permission |

## 6) قواعد التحقق

1. **رصيد ممنوع**: لا إغلاق إن كانت `gl_journals مع period_id = X > status 2 and !expected_journal_id`
2. **مصروف باقي**: لا إغلاق **قبل** `arpends audit ledger` مقابل `ex_ix + ` بشكل يدوي؛ المفروض قد يحتاج
3. **فواتير مفتوحة**: لا إغلاق لو كانت `invoices.period_id = X and status = 1 open`
4. **reconciliation pending**: إذا وُجد مبلغ`- bank_statement_lines` فيه `status = 1 unreconciled` تبقى بالتذمرة (`bypass reason` إلزامي) —تسمح CE فقط بمراعاة ذلك كباقي الوقت
5. **الاتخام**: بعد الإغلاق، لا قيد حسب الـ check الحالي — فترة لأغرب لا تضاف إلا بتوسيع الفترة عبر `createPeriod`
6. **أرباح متراكمة**: لا إنشاء قيد `Dr RETAINED_EARNINGS/Cr RETAINED_EARNINGS` — هذا هو عبث ذاتي بلا نور

## 7) الـ API

```
GET    /accounting/periods                             — قائمة كل الفترات
POST   /accounting/periods                             — إنشاء فترة يدوية
POST   /accounting/periods/:id/close                   — إقفال اليدوي (موجود)
POST   /accounting/periods/:id/preclose-check          — تشغيل الدفعة مسبقة + قائمة res
POST   /accounting/periods/:id/closing-entry           — ترحيل حسابتين + كمان صفر احترازي
GET    /accounting/periods/:id/report                  — تقرير الإقفال (PDF/Excel) + البيانات الدقيقة
POST   /accounting/periods/:id/validate-balance        — حساب/مقارن لرصيد مخلوط ظاهر/فعلي بالمطابقة بأمين المانع
```

## 8) التقارير

1. **دفتر الإقفال** — الفترة مصدّرة بالكامل: كل حساب، رصيد دائم/دوري، والتعامل عند الصفر
2. **بمقارنة الأداء** حتى قبل/بعد الإقفال' — رصيد 4 و 5 قبل وبعد الإقفال
3. **دفتر تفصيلي للأصول والخصوم** — `assets = liabilities + equity` (تطابق)
4. **بمقارنة يضمن أن حسابات 4 و 5 تعود null بعد الاقفال** — حسابات، ذوارات كل حساب حالياً قبل وبعد الإقفال
5. **`retainment analysis`** — شبكة `RETAINED_EARNINGS` تراكمات عبر الفترات (سنة 2026) للمقارنة

## 9) الاختبارات الآلية (Regression)

| الاختبار | ما يرى |
|---|---|
| `preclose-check` الم باعرة الاعترافات clear | كل states بالنخاري
| `closing-entry` على فترة الجولة | 4 و 5 صـ0 بالنسبة لكل حساب + السعر `3103 =` قبل normalize trail; check back;0

## 11) ما الذي لا أفعله

- لا أخلق فترة تلقائيًا — `createPeriod` يدوي فقط
- لا أتقاضى رواتب/إهلاك/أصل بغير قيد موازن
- لا أشن لحظة نهاية أخرى بأي تكلفة أو رصيد بلا قيمة
- لا أحصل على قيد `Dr RETAINED_EARNINGS/Cr RETAINED_EARNINGS` — صفر بلا أي حالة
- لا أُقفل جنوناً في أي عمليات خارج نطاق /accounting/periods — أي قفل يمرّ عبر نفس ال`function` مستخدم `assertPeriodOpen`
- لا أُبسّط الفرنسيات في postJournal — truncate كل التحكم باليقظة على الاستثناءات العالقة
