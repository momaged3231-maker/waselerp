## V-06: `gl_kind` → `posting_status`

**Status: ✅ VERIFIED (fixed in P1.R2, D-13)**

- **Migration line 63:** `posting_status smallint     NULL,   -- 1 pending, 2 posted, 3 reversed (D-13: renamed from gl_kind)`
- No `gl_kind` references remain in migration (grep confirmed: 0 hits).
- Values redefined: 1 = pending, 2 = posted, 3 = reversed.
- Rationale: `gl_kind=2` (invoice-first) never recorded on receipt (invoice property). `gl_kind=3` (under inspection) redundant with `status`. Only value 1 was set, redundant with `gl_journal_id IS NOT NULL`. Renamed `posting_status` tracks posting state (pending/posted/reversed) — not derivable from `gl_journal_id` alone (reversed state needs explicit tracking).
